### Spec-to-implementation reconciliation (AV)

Every declared AC of 1.1 to 1.7 is met in code, verified per story below. Divergences and forward obligations:

- **F-5 (spec reconciliation, before Epic 3). The ownership conflict is invisible to a reconciler.** `ListRoutes` omits `owner` (Story 1.6, by design, `proto/gateway.proto:106-115`). The proto defines "already correct" as `tunnel_id` + `remote_endpoint` equality alone. Create is the only RPC that surfaces `FAILED_PRECONDITION` (Story 1.4). So if resource B declares the same `local_ip`/`tunnel_id`/`remote_endpoint` as a row A holds, B's reconciler sees "already correct", never calls Create, and reports Ready on a row it does not own. Story 3.4 ("fail legibly") never fires. B's finalizer then deletes nothing (`existed=false`), and A's deletion silently removes B's tunnel until B's next resync claims the free row. *Source: ADV #1 and EC #1, found independently. Also ADV #2: an orphaned row (finalizer stripped, owner typo) blocks its `local_ip` for every other owner, and no RPC reveals or releases it.* The fix is a contract decision for Story 3.2 / AD-12: either add `owner` to `Route` and include it in "already correct", or require the reconciler to always call Create, which is idempotent for the owner. **Correction (found during correct-course):** this is not an unnoticed gap. It was a **known limit accepted on 2026-10-04** (`epics.md:698`, Epic 3 decisions: "`Converged` means the Gateway holds the declared route, not that this resource owns it"). The retro's spec reconciliation missed that note. Lilian reversed the acceptance on 2026-10-07 with that note in view (see Open questions).
- **F-6 (defer amendment).** The deferred `statement_timeout` fix (`deferred-work.md`, 1.5 #4 and 1.6 #3) says it would yield "a retryable UNAVAILABLE". But `statement_timeout` raises SQLSTATE `57014`, which `classify_sqlstate` maps to `Internal`, and a test pins that mapping (`src/store/error.rs`, case `"57014"`). `40001`, `40P01` and `55P03` are also `Internal`. As written, the deferred fix would not reach its stated outcome. *Source: ADV #3, verified.* (1.5 triage #5 rejected reclassifying 40001/40P01 on its own; this finding is about the interaction with the deferred timeout.)
- **F-7 (fix: doc, low).** The proto's size note says "roughly 7,000 routes at maximum field widths" (`proto/gateway.proto:97-101`), but bounds count characters. A 255-char `tunnel_id` of 4-byte UTF-8 is 1,020 bytes, so the real ceiling is about 3,000 routes against tonic's 4 MiB limit. *Source: ADV #7, arithmetic verified: `remote_endpoint` is ASCII-only by validation.*
- **F-8 (fix: doc, trivial).** The `kind/cluster.yaml:3-4` header still omits `examples/list_routes.rs` (`deferred-work.md`, 1.7 #13, still open). The neighbouring truncated-sentence entry (1.7 #12) was resolved in `175cc47` by dropping the dangling "and", inside a sprint-status `docs:` commit. The original reason is still not recorded.

### Diff-scope review (bmad-review lenses)

- **F-9 (fix now, before Story 2.3). Content-only validation lets NUL and control characters reach Postgres.** `validate_tunnel_id` and `check_owner` check length and emptiness only (`validation.rs:35-53`). A `tunnel_id` with `\0` reaches the upsert. **BEH: observed live:** `INVALID_ARGUMENT "rejected by the database: error returned from database: invalid byte sequence for encoding \"UTF8\": 0x00 …"`. The database is acting as the primary check rather than a backstop, and raw driver text leaks to the caller. On Delete, an owner containing NUL returns an error instead of the promised `existed=false`. The same gap underlies the open CR/LF log-forging deferral (1.5 #2, 1.1 #5). *Source: ADV #5 + BEH.* Rejecting control characters is a new bound, and Story 2.3's CRD must mirror it (AD-15), so it is cheapest before Epic 2.
- **F-10 (fix now, low).** No offline test sends a malformed or non-canonical `local_ip` to either handler. The store is keyed on the raw string (`gateway.rs:139-145,194`) and the cache on the parsed `Ipv4Addr`. They agree only because `Ipv4Addr::from_str` is strict, and nothing asserts that. *Source: VG #3, ADV #9.* Guard: handler tests for `"10.0.0.999"`, `"010.0.0.5"` and `" 10.0.0.5"` asserting `InvalidArgument` and an unchanged cache. Optionally pass `local_ip.to_string()` to the store so the key is canonical by construction.
- **F-11 (fix now, low).** Nothing checks that the two schema copies stay identical (`migrations/01_init_routing_table.sql`, `k8s/12-configmap-initdb.yaml`). AGENTS.md and the `validation.rs` doc state it as a manual rule. A drift would pass check, test, check-sqlx and local smoke, then fail every kind write with `INTERNAL` (`42703`) while readiness reports SERVING. *Source: VG #2, verified: `grep -rn include_str src` is empty.* Guard: an `include_str!` test in `validation.rs` that compares the `CREATE TABLE` bodies and asserts the `VARCHAR` widths equal the consts.
- **F-12 (fix now, low).** No test bounds how long a failing store call takes. Dropping `.acquire_timeout(...)` brings back sqlx's 30s default and every test still passes, only slower. The doc comment on `Store::unreachable` (`src/store/mod.rs:56-57`) reads as if the timeout is covered. *Source: VG #1.* Guard: assert `Store::unreachable().ping()` fails `Unavailable` within 2s.
- **F-13 (defer, attach to the statement_timeout cluster).** The readiness ping shares the 5-connection RPC pool (`store/mod.rs:44-49`, `health.rs:59-61`). Five hung queries starve the ping, readiness flips to NOT_SERVING, and with `replicas: 1` the Service loses its only endpoint while Postgres is healthy. *Source: ADV #8, EC #3.* This only becomes reachable through the unbounded post-acquire time that is already deferred.
- **F-14 (accept).** A row whose `local_ip` does not parse (only possible out of band) is returned by `ListRoutes` but cannot be deleted through the API, because delete parses strictly. AD-14 forbids a reaper, so no reconciler GCs unmatched rows. *Source: EC #2.*
- **F-15 (accept).** `owner` is unbounded and echoed in logs and the delete `status_message`. The 2026-10-04 decision rejects only the empty string (1.4 triage #3). Operator-originated owners are bounded by Kubernetes name limits. *Source: ADV #6.*
- **F-16 (reject).** `SERIAL` sequence exhaustion or a `vpn_routes_pkey` collision mapping to `INVALID_ARGUMENT`: it needs about 2^31 creates or out-of-band inserts. *Source: ADV #4, EC #4.* Negligible at this scale.
- **F-17 (defer, low).** `sqlx::Error::Configuration` (a malformed `DATABASE_URL`) exits as "unexpected database failure". *Source: ADV #10.* Fits the open 1.1 deferral on fatal startup errors.
- **F-18 (accept).** `TunnelResponse` says "created" for an insert, an own-row update and a no-op rewrite alike, with no flag. *Source: ADV #11.* No AC needs it; revisit if Story 3.3's status needs it.
- **F-19 (defer, low).** SQLSTATE `25006` (read-only) maps to `Internal`, and readiness (`SELECT 1`) stays SERVING on a read-only database. *Source: EC #5.* Take it with F-6.

## Open questions

All three were resolved by Lilian on 2026-10-07, after the verdict. All three are to land **before Epic 2**.

1. **F-5: `owner` goes on the wire.** `Route` gains `string owner = 4`. "Already correct" becomes `owner == self` and `tunnel_id` and `remote_endpoint` equal by exact string. A matching row held by another owner is a conflict that Story 3.4 surfaces, with no RPC call. "Always call Create" was ruled out because it breaks Story 3.2's zero-call AC and FR-16. This amends AD-12 ("exactly three fields") and Story 1.6's "owner never on the wire" AC. `id` and `created_at` stay off the wire.
2. **F-9: `tunnel_id` becomes an identifier: `^[A-Za-z0-9][A-Za-z0-9._-]*$`, 1 to 255 characters.** `owner` stays format-free (the 2026-10-04 decision) but rejects control characters (`\x00-\x1F`, `\x7F-\x9F`). Both are new bounds in the five-place list (`validation.rs`), so Story 2.3's CRD markers mirror them. Characters then equal bytes for `tunnel_id`, which also settles F-7.
3. **F-20: a `#[sqlx::test]` harness behind a new `make test-db`**, which needs `make db-up`. `make test` stays offline. It covers create success with the cache updated, `OwnedByAnother` with the cache untouched, concurrent foreign creates, `ListRoutes` against a disagreeing cache, the `existed`-guarded cache removal, and `owner` on the wire.
